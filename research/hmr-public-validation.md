# Public Preview HMR Validation

## Scope

This record covers the Vite HMR path used by the managed public development preview. It does not describe the production deployment path.

## Configuration boundary

The development server binds to the managed local listener and presents a browser-side HMR target using `wss`, the public preview origin, and port `443`. The proxy terminates TLS and forwards the upgraded connection to Vite's local WebSocket listener.

## Verification performed

On 17 August 2026, the local Vite listener accepted a `vite-hmr` upgrade with `HTTP/1.1 101 Switching Protocols`. The public preview then completed a `wss` WebSocket handshake using the exact token generated by its served `/@vite/client`; the negotiated subprotocol was `vite-hmr`.

> A manual connection without Vite's current token is not an HMR validity test. The recorded acceptance check uses the generated client configuration and token path.

## Outcome

The public HMR route is reachable after a refreshed preview load. The earlier close-before-open message is treated as a transient stale-session or token mismatch observation rather than an application error. Any recurrence should be checked against the generated HMR token and public origin before changing application code.

## Follow-up validation

The HMR client timeout is set to 60 seconds so a managed-origin WSS attempt is not abandoned during a slow restored preview session. After restarting the development server, a new public preview session loaded successfully with no WebSocket or Vite error recorded in the browser console.
